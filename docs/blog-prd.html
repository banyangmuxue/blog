01

背景与目标

作者需要一个不被平台格式与算法限制、可长期积累的内容阵地。访客进入博客时通常只有两个目标：找到某个主题的文章，或随意浏览近期内容。当前个人博客常见的问题是只有一条时间线列表，旧文章无法被再次找到，站点信息与友链每次调整都要改代码，评论区也缺少可控的公开机制。

问题 → 产品回应

内容沉不下去 → 分类、标签、搜索、归档四条检索路径；互动不可控 → 评论与留言先审后发；维护依赖开发 → 文章、分类标签、友链、站点信息全部后台化。

产品边界

前台不建立读者账号体系，阅读、评论、留言均为匿名行为；后台仅一个管理员账号，不引入多作者与角色权限。

期望的可观察结果

  • 访客不登录即可读完任意已发布文章，并能从分类、标签、搜索、归档四种入口重新回到文章。
  • 作者可在后台完成文章从草稿、发布、下线到再发布的完整生命周期，无需修改代码或数据库。
  • 读者提交的评论与留言不会立即公开，只有作者审核通过后才出现在前台。
  • 站点名称、公告、关于我、友链、社交链接可由后台修改，前台下次加载即可看到新内容。
  • 访客在移动端与桌面端都能完成阅读和评论，不出现横向滚动或操作入口丢失。
Default assumptions / 本文默认假设

单管理员（作者本人）；评论审核默认开启且可在站点配置中关闭；评论与留言提交需轻量人机校验与频率限制；图片与头像单文件不超过 2MB；阅读量按文章详情页加载计数。以上均待第 06 节确认。

02

范围与优先级

P0 只覆盖两条最小完整旅程：访客找到并读完文章、留下一条可被审核的评论；作者登录后发布一篇文章并处理一条评论。所有 P0 模块都为这两条旅程服务。

角色

角色身份可以做什么不能做什么
访客未登录的任何人浏览已发布文章、分类、标签、搜索结果、归档、关于我、友链、留言板；提交评论与留言；下载文章附件（P1）不能查看草稿、已下线文章、待审核评论/留言；不能进入后台；不能编辑或删除自己提交的内容
管理员唯一账号，即作者本人登录后台；管理文章、分类、标签、评论、留言、友链、站点配置与个人资料不存在读者账号；不引入多作者、审核员等第二角色

03

角色与产品模型

全站以“文章”为主对象，分类、标签、评论围绕文章组织；留言板、友链、站点配置是独立对象。所有模块的可见性只由“内容状态”和“角色”两个维度决定。

对象与关系

对象定义关键属性关系
文章一篇可发布的 Markdown 内容标题、slug、摘要、正文、封面、状态、置顶、允许评论、发布时间、浏览量属于 1 个分类；拥有 0—5 个标签；拥有多条评论
分类文章的一级归类，前台导航入口名称、slug、描述、排序1 个分类包含多篇文章；有文章时不可删除
标签文章的主题标记，可多选名称、slug与文章多对多；删除标签仅解除关联
评论访客针对某篇文章的匿名发言昵称、邮箱（不公开）、内容、状态、博主回复必须属于一篇已发布文章；文章删除时一并删除
留言访客在留言板发布的独立内容昵称、邮箱（不公开）、内容、状态、博主回复不关联文章；文章删除不影响留言
友链作者维护的外部站点链接名称、URL、描述、头像、排序、显示状态独立列表；前台只展示显示状态
站点配置全站唯一的站点级设置站点信息、公告、功能开关、社交链接、页脚单例，所有前台页面读取
管理员唯一后台账号用户名、密码、作者资料单账号；拥有全部后台权限

文章状态机

状态前台可见可编辑可操作评论
草稿否（直接访问返回 404）是编辑、预览、发布、删除不展示评论区
已发布是是编辑、下线、置顶、删除按文章的“允许评论”开关执行
已下线否（直接访问返回 404）是编辑、重新发布、删除评论保留，重新发布后恢复展示
已删除否否不可恢复评论一并删除

状态流转：草稿 → 发布 → 已发布 → 下线 → 已下线 → 再发布 → 已发布。任意状态均可删除，删除为不可逆操作，必须二次确认并展示将被一并删除的评论数量。

评论与留言状态

状态前台公开列表后台列表作者可执行操作
待审核不展示；提交者仅看到“审核中”提示展示通过、驳回、删除
已通过展示展示驳回、回复、删除
已驳回不展示展示改为通过、删除
已删除不展示不展示（不可恢复）无
  • 审核开关默认开启；关闭后新提交内容直接进入“已通过”，存量待审核内容不会自动通过。
  • 博主回复只针对“已通过”的评论/留言；回复不触发再次审核，前台以“博主”标识展示。
  • 评论与留言的内容仅按纯文本展示，不解析 HTML；昵称可重复，邮箱永不公开。
  • 匿名访客没有身份凭证，因此不能编辑或撤销自己提交的评论与留言；如需删除需联系作者。

功能需求

每个模块给出目的、触发条件、处理规则、结果与异常。跨模块复用的校验、排序、删除、防滥用规则统一收敛在第 05 节，模块内只引用不重复定义。

前台模块 · FR-01—FR-09

FR-01

首页

P0
Purpose访客首次进入时，在首屏判断站点是否有自己需要的内容，并进入文章或检索入口。
Trigger访客打开站点根路径，或从外部链接进入首页。
Layout

顶部导航；Hero 区（站点名、副标题、一句话简介、搜索框、主按钮“浏览文章”）；可选公告条；置顶文章区（最多 3 篇）；最新文章区（6 篇，双列卡片）；分类快捷入口（最多 6 个）；作者卡片（头像、昵称、简介、“关于我”入口）；页脚。

Rules
  • 只展示“已发布”文章；草稿、已下线不出现在任何区块。
  • 置顶文章按置顶顺序展示，最多 3 篇；没有置顶时隐藏整个置顶区，不显示空占位。
  • 最新文章按首次发布时间倒序，最多 6 篇；不足 6 篇按实际数量展示。
  • 分类按后台排序值升序，只展示包含已发布文章的分类，最多 6 个。
  • 站点名称、副标题、简介、公告来自站点配置；字段为空时隐藏对应模块，不显示空标签。
  • 搜索框去除首尾空格后非空才可提交，回车或点击按钮跳转搜索结果页。
  • 公告支持关闭，关闭状态只保留在当前浏览会话，不写入服务端。
Result

访客可以进入任意文章、分类页、搜索页、关于我页面；页面无死链，首屏在 768px 高度内可见主标题与至少一篇内容入口。

Exceptions
  • 文章区块加载失败：该区块显示错误提示与“重试”，其他区块正常展示。
  • 全站没有已发布文章：最新文章区显示空态“还没有文章”，并提供“关于我”入口；不展示后台入口。
  • 站点配置暂不可用：使用默认站点名“我的博客”和默认简介，页面不白屏。
FR-02

文章列表与详情

P0
Purpose提供全量已发布文章的时间线浏览，并让访客在详情页完成一次完整阅读。
Trigger点击导航“文章”、首页“浏览文章”、分类/标签/搜索结果、归档条目或上一篇/下一篇。
Article list
  • 入口 /articles；每页 10 篇，按首次发布时间倒序。
  • 卡片包含封面、标题、摘要、分类、标签、发布时间、浏览量；封面缺失时使用纯色几何占位。
  • 列表右侧提供分类、标签、归档入口；移动端收进筛选抽屉。
  • 分页显示上一页、页码、下一页；只有一页时隐藏分页。
Article detail
  • 入口 /post/:slug；展示标题、发布时间、更新时间（有更新时）、浏览量、分类、标签、封面、Markdown 正文。
  • 正文支持代码高亮与“复制代码”、图片点击放大、表格横向滚动、外链新窗口打开。
  • 正文包含至少 3 个二级标题时，桌面端显示文章目录；目录随滚动高亮当前章节。
  • 正文后展示上一篇/下一篇（按发布时间相邻），再往下是评论区。
  • 浏览量在详情页加载时计数；同一访客对同一文章 30 分钟内重复加载不重复计数。假设
  • 文章关闭评论时，既有已通过评论仍展示，只隐藏评论表单并提示“本文评论已关闭”。
Result

访客能完整阅读正文并通过目录跳转章节；从列表、搜索、分类、标签、归档任意入口进入详情后都可返回原入口。

Exceptions
  • 文章不存在、为草稿或已下线：统一返回 404 页面，提供“返回文章列表”。
  • 正文加载失败：显示错误提示与重试，不展示半截正文。
  • 图片加载失败：显示占位图与替代文本，不撑破版式。
  • 摘要或封面缺失：使用自动摘要与几何占位，不出现空白卡片。
  • 评论区加载失败：正文正常展示，评论区单独提示重试。
FR-03

分类与标签

P0
Purpose让访客按主题而不是按时间重新组织文章，解决旧文章沉底问题。
Trigger点击首页分类入口、文章卡片上的分类/标签、导航“分类”、标签云或侧栏分类列表。
Rules
  • 分类页 /categories/:slug：展示分类名称、描述、已发布文章数、文章列表（每页 10 篇）与分页。
  • 标签页 /tags/:slug：展示标签名称、已发布文章数、文章列表与分页；/tags 展示全部标签云。
  • 一篇文章只能属于 1 个分类，可有 0—5 个标签；分类与标签名称 2—20 字且不可重名。
  • 前台只展示包含已发布文章的分类与标签；只有草稿的分类不出现在任何前台入口。
  • 分类被删除前，其下文章数（含草稿）必须为 0；标签被删除时自动从所有文章解除关联。
  • 分类/标签不存在时返回 404；存在但无已发布文章时展示空态“该分类下暂无文章”。
Result

访客可通过分类或标签连续浏览同主题文章，分页与排序规则与文章列表一致。

Exceptions
  • 分类页文章加载失败：显示区块错误与重试，分类标题与描述仍展示。
  • 标签被删除后旧链接访问：返回 404，并提供标签总览入口。
FR-04

搜索

P0
Purpose访客记得关键词但记不住标题或时间时，仍能快速定位文章。
Trigger顶部导航搜索按钮、首页搜索框或搜索结果页搜索框提交关键词。
Rules
  • 关键词去除首尾空格后长度 1—50 字；为空时提示“请输入关键词”，不发起搜索；超过 50 字提示缩短关键词。
  • 匹配范围：标题、摘要、正文纯文本、标签名称；不区分英文大小写；特殊字符按普通文本处理，不支持引号、AND/OR 等高级语法。
  • 排序：标题命中优先，其次按首次发布时间倒序；同篇文章只出现一次。
  • 结果项展示标题（关键词高亮）、摘要片段（命中位置前后各 40 字）、分类、发布时间；正文命中但摘要未命中时，摘要替换为命中片段。
  • 只搜索已发布文章；草稿、已下线、待审核评论不进入搜索范围。
  • 每页 10 条，显示结果总数与当前关键词。
Result

搜索页 /search?q=关键词 展示结果列表；点击结果进入对应文章详情。

Exceptions
  • 无结果：展示空态“没有找到相关文章”，附最新 3 篇文章与分类入口。
  • 关键词为空：展示搜索说明、热门标签与最新文章，不显示结果列表。
  • 搜索失败：保留关键词与输入框内容，提示“搜索失败，请重试”。
FR-05

归档

P0
Purpose为按时间回看的访客提供按月索引，形成博客的“年轮”。
Trigger点击导航“归档”、首页归档入口或文章列表侧栏归档。
Rules
  • 归档页 /archive：按年份倒序分组，年份内按月份倒序分组。
  • 每个年份显示文章总数；每个月显示月份与文章数；文章行显示日期与标题。
  • 默认展开最近一个有文章的年份，其余折叠；点击年份或月份标题展开/收起。
  • 展开状态只保留在当前浏览会话，不写入服务端。
  • 只展示已发布文章；发布时间缺失的异常数据不出现在归档。
Result

访客可在一页内看到全部文章的时间分布，并直接进入任意文章。

Exceptions
  • 没有已发布文章：显示空态“暂无归档内容”，并提供最新文章入口。
  • 归档加载失败：显示错误提示与重试。
FR-06

文章评论

P0
Purpose让访客无需注册即可对文章表达观点，同时保证公开内容经过作者审核。
Trigger访客在已发布且允许评论的文章详情页底部填写并提交评论。
Display
  • 仅展示“已通过”的评论，按提交时间正序（旧→新）；显示楼层号、昵称、默认几何头像、时间、内容。
  • 博主回复嵌套在原评论下方，标识“博主”，可多条，按时间正序。
  • 邮箱不展示；评论内容按纯文本渲染，保留换行，不解析 HTML 与 Markdown。
  • 评论数只统计“已通过”的评论。
Form & rules
  • 昵称必填，2—20 字；邮箱选填，格式校验，不公开，仅用于 P1 回复通知；内容必填，5—500 字。
  • 提交前需完成一次轻量人机校验；同一浏览器 60 秒内只能提交一次，同一 IP 10 分钟内最多 3 条。假设
  • 审核开启时，提交成功提示“评论已提交，审核通过后展示”；审核关闭时立即展示并滚动定位到新评论。
  • 提交失败时保留昵称、邮箱与内容，仅在内容区下方展示错误原因。
Result

评论进入待审核列表（或直接通过），仪表盘待审核数 +1；访客看到明确的审核中反馈，不会误以为评论已公开。

Exceptions
  • 文章关闭评论：隐藏表单，展示“本文评论已关闭”；已有已通过评论照常展示。
  • 文章已下线或被删除：详情页 404，评论区不可见。
  • 人机校验失败：提示重新完成校验，内容保留。
  • 触发频率限制：提示“提交过于频繁，请稍后再试”，按钮进入倒计时不可用。
  • 内容仅含空白或超长：阻止提交并在字段下方提示字数要求。
FR-07

关于我

P0
Purpose让访客了解作者身份、关注领域与联系方式，建立对站点的信任。
Trigger点击导航“关于”、首页作者卡片或页脚关于链接。
Layout & rules
  • 页面 /about：头像、昵称、一句话简介、技能标签、社交链接、Markdown 长文、建站日期。
  • 头像、昵称、简介、技能、长文来自个人资料；社交链接与建站日期来自站点配置。
  • 技能标签最多 8 个，每个 2—12 字；无数据时隐藏该组。
  • 社交链接只允许 http/https，前台新窗口打开；无链接时隐藏链接组。
  • 长文使用与文章正文相同的 Markdown 渲染规则。
  • 所有字段都为空时展示默认文案“这个作者还没有填写介绍”。
Result

访客能看到作者的完整介绍与可点击的外部联系方式；页面无内容时也不出现空白板块。

Exceptions
  • 资料加载失败：显示默认文案与重试入口，页面不白屏。
  • 头像加载失败：显示昵称首字母占位头像。
  • 链接格式非法：后台保存时阻止，前台不出现不可点击文本。
FR-08

友链

P0
Purpose展示作者认可的站点，形成博客之间的互相导流。
Trigger点击导航“友链”或页脚友链入口。
Rules
  • 页面 /links：卡片网格，每项展示头像、名称、描述、站点地址。
  • 只展示“显示”状态的友链；按排序值升序，排序值相同按创建时间升序。
  • 点击卡片新窗口打开目标站点，并使用安全的窗口打开属性。
  • 友链新增、编辑、排序、显隐全部由后台维护；P0 不提供访客自助申请。
Result

访客能看到作者维护的全部公开友链，并按顺序浏览。

Exceptions
  • 无公开友链：展示空态“还没有添加友链”与邀请说明，不显示空网格。
  • 友链头像加载失败：显示名称首字母占位。
  • 友链加载失败：显示错误提示与重试。
FR-09

留言板

P0
Purpose提供不依附于具体文章的匿名交流空间，适合问候、建议与站务反馈。
Trigger点击导航“留言板”，填写昵称、邮箱与内容并提交。
Rules
  • 页面 /guestbook：顶部说明（欢迎留言、审核说明）、留言表单、留言列表。
  • 昵称 2—20 字必填；邮箱选填且不公开；内容 5—300 字必填；提交前完成轻量人机校验。
  • 留言与文章评论是独立对象，共用审核状态、频率限制与博主回复规则。
  • 留言列表按提交时间倒序，只展示“已通过”内容；博主回复展示在留言下方。
  • 访客不能编辑或删除自己提交的留言。
Result

留言进入待审核列表；访客看到“留言已提交，审核通过后展示”；作者审核通过后留言按时间倒序出现在列表顶部。

Exceptions
  • 留言板关闭：显示“留言板暂时关闭”，隐藏表单，已有公开留言仍可浏览。
  • 提交失败：保留输入并提示原因；频率限制时按钮进入倒计时。
  • 无公开留言：展示空态“还没有留言，来坐坐吧”。
  • 留言加载失败：列表区提示重试，表单仍可用。

后台模块 · FR-10—FR-18

FR-10

后台登录与账号安全

P0
Purpose保证只有作者本人能进入后台，前台任何位置不暴露后台入口。
Trigger管理员直接访问后台地址，或在会话失效后访问任一后台页面。
Rules
  • 登录页 /admin/login：用户名、密码两个字段；不提供注册、找回密码入口。
  • 登录成功进入仪表盘；失败统一提示“账号或密码错误”，不区分具体原因。
  • 连续 5 次失败锁定 10 分钟，锁定期间显示剩余时间。假设
  • 30 分钟无操作会话失效，再次访问后台跳转登录页并提示“登录已过期”。假设
  • 后台所有页面与操作均要求登录；未登录访问返回登录页，不暴露任何后台数据。
  • 退出登录后立即失效并回到登录页；前台不展示“登录后台”入口。
  • 密码修改在个人资料中完成，需校验旧密码；忘记密码由服务器运维处理。TBD
Result

只有持有正确账号密码的单一管理员能进入后台；登录失败与锁定对访问者可见，但不泄露账号信息。

Exceptions
  • 提交空字段：字段下方提示必填，不发起登录请求。
  • 登录期间网络失败：保留输入，提示“登录失败，请稍后重试”。
  • 锁定中刷新页面：仍展示剩余锁定时间，登录按钮不可用。
  • 会话在表单编辑中失效：保存操作提示“登录已过期”，当前页面表单内容保留，重新登录后需再次提交。
FR-11

仪表盘

P0
Purpose登录后的第一屏，快速回答“有多少内容、有什么待处理、下一步做什么”。
Trigger登录成功，或点击后台侧栏“仪表盘”。
Content
  • 统计卡：文章总数、已发布、草稿、已下线、待审核评论、待审核留言、累计浏览量。
  • 最近发布 5 篇文章（标题、状态、发布时间、编辑入口）。
  • 待处理 5 条评论/留言（昵称、摘要、来源文章、时间、审核入口）。
  • 快捷操作：写文章、审核评论、站点配置、个人资料。
Rules
  • 文章总数包含草稿与已下线，不包含已删除；浏览量只统计已发布文章。
  • 待审核数量为评论与留言待审核之和，任一为 0 时对应入口不显示数量气泡。
  • 点击统计卡进入对应列表并自动带上筛选条件。
  • 数字为进入页面时的实时值；执行审核或发布后返回仪表盘应重新加载。
Result

管理员在 1 屏内看到待审核压力与最近内容，并能一键进入处理页面。

Exceptions
  • 无文章：文章区展示“写第一篇文章”引导，不显示空表格。
  • 无待审核：待处理区展示“暂无待处理内容”。
  • 统计加载失败：对应卡片显示“—”，并提供刷新入口，其余卡片正常。
FR-12

文章管理

P0
Purpose作者无需改代码即可完成文章从创建到下线、删除的全部维护动作。
Trigger后台侧栏“文章”、仪表盘“写文章”或最近文章编辑入口。
List
  • 页面 /admin/posts：状态标签页（全部 / 已发布 / 草稿 / 已下线）、标题搜索、分类筛选、按更新时间倒序、每页 10 条。
  • 列：标题、分类、标签、状态、发布时间、浏览量、操作。
  • 操作：编辑、预览、发布/下线、置顶/取消置顶、删除。
  • 标题搜索对当前状态标签页内生效；筛选条件在分页间保留，可一键清空。
Editor
  • 页面 /admin/posts/new 与 /admin/posts/:id/edit。
  • 左侧：标题输入、Markdown 编辑器、工具栏（粗体、标题、链接、图片、代码、预览切换）。
  • 右侧设置面板：状态、分类、标签、封面、摘要、slug、允许评论、置顶。
  • 底部操作：保存草稿、预览、发布/更新；新建默认“草稿”。
  • 草稿只要求标题，可暂不选分类、不填正文；发布时校验标题、正文、分类与 slug 唯一性。
  • 摘要为空时自动取正文纯文本前 120 字；slug 为空时自动生成，冲突时自动追加序号。
  • 预览使用前台文章样式，不计数浏览量、不展示评论区；草稿预览仅管理员可见。
  • 首次发布写入发布时间；下线后重新发布不改变首次发布时间。
Destructive actions
  • 下线立即生效，前台详情变为 404；评论保留，重新发布后恢复展示。
  • 删除为不可逆操作：弹窗展示文章标题与评论数量，要求输入完整标题后才可确认删除，文章及其评论一并删除。
Result

保存草稿后列表状态为“草稿”；发布后文章出现在首页、列表、分类/标签页、搜索与归档，并按首次发布时间排序。

Exceptions
  • 发布校验失败：定位到第一个错误字段并提示，草稿状态不变。
  • 保存失败：保留全部已输入内容，提示重试；不自动关闭页面。
  • 存在未保存修改时离开页面或刷新：弹出确认提示。
  • 封面/头像上传失败：保留其余字段，提示重新上传，不阻止草稿保存。
  • 编辑已被删除的文章：列表刷新后该条消失，编辑页返回列表并提示。
FR-13

分类与标签管理

P0
Purpose维持前台导航与筛选口径的一致，避免删除分类导致文章失去归属。
Trigger后台侧栏“分类标签”，或文章编辑器中的“管理分类/标签”入口。
Category
  • 页面 /admin/taxonomy，分类与标签两个标签页。
  • 分类列表：名称、slug、描述、文章数（含草稿与已下线）、排序、操作。
  • 新建/编辑：名称 2—20 字且唯一，slug 自动生成且唯一，描述 ≤100 字，排序 0—999（数字越小越靠前）。
  • 分类下文章数大于 0 时禁止删除，提示“该分类下有 N 篇文章（含草稿），请先转移或删除文章”。
  • P0 不提供批量转移分类；P1 增加迁移能力。
Tag
  • 标签列表：名称、slug、文章数、操作；支持新建、编辑、删除。
  • 删除标签需二次确认，删除后自动从所有文章解除关联，文章本身不受影响。
  • 标签合并为 P1；当前只支持逐个删除。
Result

前台分类导航、分类页、标签页与后台数据保持一致；无已发布文章的分类与标签不出现在前台入口。

Exceptions
  • 名称或 slug 重复：保存时在字段下方提示，不写入。
  • 删除分类被阻止：弹窗说明文章数量与处理方式，不执行删除。
  • 删除标签后仍有请求访问旧标签页：前台返回 404 并提供标签总览。
  • 保存失败：保留表单内容并提示重试。
FR-14

评论审核

P0
Purpose让作者在公开前检查每一条评论，并在通过后进行回复。
Trigger后台侧栏“评论”、仪表盘待审核卡片或待处理列表。
List
  • 页面 /admin/comments：标签页待审核 / 已通过 / 已驳回 / 全部；按提交时间倒序，每页 10 条。
  • 每条显示昵称、邮箱、内容、所属文章（可点击预览）、提交时间、状态、操作。
  • 支持按昵称/内容搜索、按文章筛选；筛选条件在分页间保留。
  • 待审核数量显示在侧栏与仪表盘，处理完一条后数字实时减少。
Actions
  • 通过：待审核或已驳回 → 已通过；前台立即公开；操作后提示成功。
  • 驳回：待审核或已通过 → 已驳回；已通过内容立即从前台消失。
  • 删除：任意状态 → 已删除，必须二次确认，删除后不可恢复。
  • 回复：仅已通过评论可回复，内容 1—500 字；回复以后台“博主”身份展示，不触发审核，可多条。
  • 批量通过、批量驳回为 P1；P0 只支持单条处理。
Result

审核结果直接影响前台评论列表与评论数；已通过评论可继续回复；被驳回内容不公开但保留在后台可复查。

Exceptions
  • 操作失败：状态回滚到操作前，并提示重试。
  • 评论所属文章已下线：仍可在后台审核与回复，前台文章恢复后评论同步展示。
  • 评论所属文章已删除：该评论已随文章一并删除，列表不再展示。
  • 当前标签页无数据：显示对应空态，不显示空白表格。
FR-15

留言管理

P0
Purpose集中处理留言板的匿名内容，与评论使用一致的审核口径。
Trigger后台侧栏“留言”、仪表盘待审核留言卡片。
Rules
  • 页面 /admin/messages：标签页待审核 / 已通过 / 已驳回 / 全部；按提交时间倒序，每页 10 条。
  • 每条显示昵称、邮箱、内容、提交时间、状态、操作；支持昵称/内容搜索。
  • 操作与评论一致：通过、驳回、删除（二次确认）、回复（仅已通过，1—500 字）。
  • 留言与评论独立计数，互不影响；仪表盘分别展示待审核数量。
  • 留言不关联文章，因此不提供文章筛选，也不受文章删除影响。
Result

通过后留言按提交时间倒序出现在留言板顶部；回复展示在留言下方并标识“博主”；驳回或删除后前台立即不可见。

Exceptions
  • 留言板在前台被关闭：后台仍可审核现有留言，回复不会让留言板自动重新开放。
  • 操作失败：状态回滚并提示重试。
  • 无数据：按当前标签页展示空态。
FR-16

友链管理

P0
Purpose让作者自行维护前台友链列表，不再依赖代码改动。
Trigger后台侧栏“友链”，或前台友链页的“管理友链”入口（仅登录后可见）。
Rules
  • 页面 /admin/links：列表展示头像、名称、URL、描述、排序、显示状态、操作。
  • 新建/编辑字段：名称 2—30 字必填；URL 必填且只允许 http/https；描述 ≤100 字；头像选填（上传 ≤2MB）；排序 0—999；显示开关。
  • 排序值越小越靠前；排序值相同按创建时间升序。
  • 删除需二次确认，删除后前台立即移除；隐藏只影响前台展示，不删除数据。
  • P0 不支持拖拽排序与访客自助申请，均由 P1 提供。
Result

前台友链页按照后台顺序展示“显示”状态的友链；修改后前台下次加载即生效。

Exceptions
  • URL 非法：保存时阻止并提示“请输入以 http:// 或 https:// 开头的地址”。
  • 头像上传失败：保留其他字段，提示重新上传，不阻止保存文字信息。
  • 无友链：展示空态与“新增友链”按钮。
FR-17

站点配置

P0
Purpose集中维护全站级信息与功能开关，避免前台出现硬编码文案。
Trigger后台侧栏“站点配置”，或仪表盘快捷操作。
Groups
  • 基本信息：站点名称（2—30 字必填）、副标题（≤40 字）、站点描述（≤120 字）、Logo、作者昵称（2—20 字）、建站日期、备案号（≤50 字）。
  • 首页：公告内容（≤200 字）与公告开关。
  • 功能开关：评论开关、评论需审核（默认开）、留言板开关、搜索开关、附件下载开关（P1）。
  • 社交链接：平台名称、URL、排序、显示开关，最多 10 条。
  • 页脚：版权文案（≤100 字）。
Rules
  • 站点名称为空时阻止保存并定位字段；其他字段为空时保存为“未设置”，前台隐藏对应模块。
  • URL 只允许 http/https；社交链接按排序值升序展示。
  • 保存为整体提交：校验失败时不写入任何字段，保留用户已填内容。
  • 关闭评论开关：所有文章详情隐藏评论表单与评论区，既有评论数据保留；重新开启后恢复展示。
  • 关闭搜索开关：前台隐藏搜索入口，直接访问搜索页展示“搜索功能已关闭”。
  • 配置保存后，前台下次加载生效；不承诺实时推送。
Result

站点名称、公告、页脚、社交链接、功能开关在前台对应位置生效，未填写项不产生空白占位。

Exceptions
  • 保存失败：停留在当前分组，提示错误并保留内容。
  • 公告为空但开关开启：前台不展示公告条，后台提示“公告为空”。
  • 社交链接超过 10 条：阻止新增并提示上限。
FR-18

个人资料与密码

P0
Purpose维护“关于我”页面的作者信息，并提供唯一的密码修改入口。
Trigger后台侧栏“个人资料”，或右上角账号菜单。
Profile
  • 页面 /admin/profile：头像上传、昵称（2—20 字）、一句话简介（≤60 字）、技能标签（≤8 个，每个 2—12 字）、关于我正文（Markdown，≤20000 字）。
  • 头像支持 jpg/png/webp，≤2MB；上传失败时保留原头像与其他字段。
  • 昵称、简介、技能、正文保存后，前台关于我页面下次加载生效。
  • 提供“预览关于我”入口，使用前台样式打开。
Password
  • 修改密码需填写旧密码、新密码、确认新密码；新密码 8—32 位且同时包含字母与数字。假设
  • 旧密码错误或两次新密码不一致时阻止提交，并在对应字段提示。
  • 修改成功后当前会话立即失效，跳转登录页并提示“密码已修改，请重新登录”。
Result

关于我页面展示最新的作者资料；密码修改后旧密码无法再登录，必须使用新密码重新进入后台。

Exceptions
  • 资料保存失败：保留表单内容并提示重试。
  • 正文超长：阻止保存并提示字数上限。
  • 未修改任何字段就保存：提示“没有需要保存的修改”，不发起请求。
  • 修改密码时登录失效：跳转登录页，已填写内容不保留（安全考虑）。
05

共享规则与异常

以下规则被多个模块引用，只在此处定义一次。模块内出现冲突时，以本节为准。

5.1 分页、排序与计数

场景规则
前台文章列表 / 分类 / 标签 / 搜索每页 10 条，按首次发布时间倒序；搜索标题命中优先
归档年份倒序 → 月份倒序 → 文章发布时间倒序
后台文章列表每页 10 条，默认按更新时间倒序
后台评论 / 留言每页 10 条，按提交时间倒序
前台评论列表按提交时间正序；回复按时间正序嵌套
首页最新文章按首次发布时间倒序，最多 6 篇
评论数只统计“已通过”评论；回复不计入评论数
浏览量详情页加载计数；同一访客同文章 30 分钟内不重复假设

5.2 文本与字段校验

字段规则校验时机
站点名称必填，2—30 字站点配置保存
文章标题必填，2—80 字草稿保存 / 发布
文章正文发布时必填发布
文章摘要≤200 字保存 / 发布
分类 / 标签名称2—20 字，不可重名分类标签保存
昵称必填，2—20 字，允许重复评论 / 留言提交
邮箱选填，≤100 字符，需符合邮箱格式评论 / 留言提交
评论内容5—500 字，纯文本评论提交
留言内容5—300 字，纯文本留言提交
博主回复1—500 字后台回复
友链名称 / URL名称 2—30 字；URL 必填且为 http/https友链保存
密码8—32 位，含字母与数字修改密码
头像 / 图片jpg / png / webp，≤2MB上传时

5.3 匿名互动与防滥用

  • 评论与留言均需完成一次轻量人机校验；校验失败不消耗提交次数。假设
  • 同一浏览器 60 秒内只能提交一条评论或留言；同一 IP 10 分钟内最多 3 条。假设
  • 提交内容只接受纯文本，HTML 标签按文本转义展示；文章正文中的脚本不得执行。
  • 昵称允许重复，不作为身份凭证；邮箱不公开、不用于前台展示。
  • 敏感词过滤为 P1；当前由作者人工审核兜底。
  • 发现垃圾内容时作者可驳回或删除；删除为最终处理，不保留前台入口。

5.4 空态、加载与错误

场景表现
列表加载中骨架屏占位，不显示空白列表
列表为空空态文案 + 下一步入口（返回列表 / 写第一篇文章 / 浏览其他分类）
区块加载失败该区块显示错误提示与“重试”，其余区块不受影响
表单提交失败保留已填内容，字段级错误就近展示，整体错误用顶部提示
文章不存在 / 草稿 / 已下线统一 404 页面，提供返回文章列表
未登录访问后台跳转登录页，登录成功后回到原目标页
会话失效提示“登录已过期”，跳转登录页
图片加载失败占位图 + 替代文本，保持原有版式

5.5 删除与不可逆操作

操作确认方式后果
删除文章弹窗展示标题与评论数，需输入完整标题确认文章与全部评论删除，前台立即不可访问，不可恢复
删除评论 / 留言二次确认弹窗从前台与后台列表移除，不可恢复
删除友链二次确认弹窗前台立即移除，不可恢复
删除分类先检查文章数有文章时禁止；无文章时二次确认后删除
删除标签二次确认弹窗解除所有文章关联，文章保留
下线文章二次确认弹窗前台 404，数据与评论保留，可重新发布
修改密码旧密码校验当前会话失效，需重新登录

5.6 时间与展示口径

  • 所有时间按 Asia/Shanghai（UTC+8）展示。
  • 发布时间 7 天内显示相对时间（如“3 天前”），超过 7 天显示 YYYY-MM-DD；评论与留言显示到分钟。
  • 文章详情同时显示首次发布时间与最后更新时间；更新时间与发布时间同一天时不重复展示。
  • 归档与后台列表中的日期使用 YYYY-MM-DD，时间使用 YYYY-MM-DD HH:mm。

5.7 草稿与隐私边界

  • 草稿与已下线文章不出现在首页、列表、分类、标签、搜索、归档、RSS 与任何公开接口。
  • 草稿预览仅管理员登录后可用，预览页不进入任何公开索引。
  • 待审核与已驳回的评论/留言不出现在前台，也不出现在前台计数中。
  • 访客邮箱只在后台可见，前台任何位置不展示，也不通过接口返回。
