01

设计基准

暗色科技风不等于大面积霓虹。页面以深蓝黑为底、细网格为环境纹理，用青色作为唯一主强调色、紫色作为次强调色；正文区域降低装饰密度，优先保证长文阅读的对比度与节奏。

关键词

冷静、专注、可读性优先。装饰只出现在导航、Hero、页脚与卡片悬停，不进入正文段落。

视觉记忆点

左上角 B/ 渐变 Logo、Hero 右侧终端卡片、青色细线分隔、等宽字体的元信息与状态标签。

禁止项

不使用大面积高饱和渐变、发光文字、玻璃拟态堆叠、彩色阴影；正文不铺网格背景。

1.4 动效与交互反馈

时长

悬停 160ms；展开/收起 220ms；弹窗 240ms；页面不做过场动画。统一 ease-out。

可访问性

键盘焦点使用 2px 青色描边 + 2px 偏移；支持 prefers-reduced-motion；正文对比度不低于 4.5:1。

  • 卡片悬停只改变边框亮度与 2px 上浮，不缩放图片、不改变阴影方向。
  • 所有可点击区域最小 40×40px；移动端底部操作区预留 16px 安全间距。
  • 成功操作用右上角 Toast（3 秒自动消失）；破坏性操作使用居中弹窗，不使用 Toast 代替确认。
02

信息架构

前台以“发现 → 阅读 → 互动”组织，后台以“概览 → 内容 → 互动 → 站点”组织。前台导航只保留最高频入口，分类与标签收进文章页侧栏，避免一级导航过长。

03

前台与后台共享同一套色彩、字体与控件状态，但信息密度不同：前台强调阅读与发现，后台强调扫描、筛选与批量操作。

3.4 内容排版规格

文章正文

正文 15px / 1.75；段落间距 16px；H2 上下 40/16，H3 上下 28/12；正文区最大 760px；图片宽度 100%，圆角 10，点击放大；代码块带顶部栏与复制按钮。

后台表格

行高 56px；表头 12px 等宽；首列为可点击标题；操作列右对齐；状态用色点 + 文本；空表不显示表头以外的空白骨架。

  • Markdown 正文中的外链统一新窗口打开，并在链接尾部显示 ↗ 标识。
  • 代码块超过 12 行时内部滚动，不撑宽页面；复制成功后按钮文案变为“已复制”2 秒。
  • 表格宽度超过正文时横向滚动，单元格不换行挤压。

06

交互、状态与映射

前五章回答“每个页面长什么样”，本章回答“页面之间怎么流动、异常时怎么表现、需求落在哪一页”。评审时可按 6.6 的映射表逐条核对，确认每条 FR 都有对应页面与状态说明。

6.1 关键流程

四条主流程覆盖 P0 的全部闭环：读者阅读并评论、作者写作并发布、作者审核评论、访客留言。每一步都落在已有页面上，不额外引入中间页。

流程 A · 访客阅读并提交评论

01 · P-01进入首页置顶与最新文章，选择一篇进入详情
→
02 · P-03阅读正文目录定位、代码复制、上下篇跳转
→
03 · 评论区填写评论昵称 / 邮箱 / 内容，完成人机校验
→

→

  • 提交后不跳转、不清空正文以外的上下文；成功后表单清空并显示“审核中”提示，60 秒内按钮不可再次提交。
  • 审核未通过或删除的评论，前台任何入口都不可见；提交者不会收到通知邮件（P0 不做通知）。

→

  • 离开编辑器时若有未保存修改，弹出确认；确认离开后本次编辑内容丢弃，已保存版本不受影响。
  • 发布失败（如 slug 冲突、必填缺失）保留全部输入并定位到出错字段，不新建重复草稿。

6.2 状态矩阵

以下状态适用于全部 20 个页面。实现时每个异步区块都必须能从加载态进入空态、错误态与成功态，不允许出现“白屏无提示”。

状态触发条件界面表现退出方式
加载中请求已发出、未返回内容区骨架屏（列表 3 行、详情标题 + 段落占位）；主按钮进入 loading 并禁用，防止重复提交数据返回进入成功／空态；超过 8 秒转错误态
空数据请求成功但结果为 0 条空态图形 + 一句说明 + 一个主操作（如“清除筛选”“去写第一篇”）；不显示分页器执行主操作或修改筛选条件
加载失败网络异常或服务端 5xx保留导航与页面框架，内容区显示“加载失败”与“重试”按钮，附简短原因点击重试成功；或返回上一级
提交中表单提交请求进行中提交按钮 loading、文案变为“提交中…”；输入框只读，避免重复修改请求返回后进入成功或失败

会话失效后台请求返回 401跳转 A-01，提示“登录已过期，请重新登录”；编辑器有未保存内容时先提示重新登录后回到仪表盘
未登录直达访问任意 /admin 路由跳转 A-01 并携带原路径，登录成功后回到该页完成登录

审核中评论／留言已提交、未审核前台不展示该条内容；提交者仅看到一次成功提示，无持续状态标识后台通过或驳回后结束
操作禁用分类下有文章、登录锁定中、无修改时保存按钮置灰并附原因（hover 提示或行内说明），点击不产生请求满足条件后自动恢复可用

6.3 反馈与确认规则

Toast

右上角，成功 3 秒自动消失；失败保留 5 秒且可手动关闭。失败文案必须包含原因与下一步，例如“保存失败，请重试”。

行内提示

字段校验、字数计数、密码规则、URL 格式全部就近显示，不使用弹窗打断填写。

确认弹窗

破坏性操作一律居中弹窗，展示对象名称与后果；删除文章要求输入完整标题，主按钮为红色且默认聚焦“取消”。

  • 确认弹窗与 Toast 不能互换：确认用于不可逆操作，Toast 只用于结果通知。
  • 弹窗支持 Esc 关闭、点击遮罩关闭；删除确认弹窗点击遮罩不关闭，避免误触。
  • 同一屏同时最多显示 3 条 Toast，超出后排队；相同文案 5 秒内合并为一条。
  • 所有失败提示保留用户已填内容；只有成功提交才清空表单。

断点前台后台关键变化

  • 390px 为移动端验收基准：导航、搜索、评论表单、后台表格卡片化都必须在该宽度可用。

6.5 无障碍与键盘操作

  • 页面按 H1 → H2 → H3 层级组织，文章正文标题从 H2 开始，不跳级。
  • 所有表单控件绑定 label；错误提示与字段通过 aria-describedby 关联，提交失败后由 aria-live 播报。
  • 状态不能只用颜色表达：状态点必须配合文字（草稿／已发布／待审核／已驳回）。
  • Tab 顺序遵循视觉顺序；弹窗打开后焦点移入弹窗并循环，Esc 关闭后焦点回到触发按钮。
  • 列表与表格提供“跳到正文”链接；图片必须有 alt，纯装饰图形使用空 alt。
  • 尊重 prefers-reduced-motion：关闭骨架屏闪烁、卡片上浮与 Toast 位移。
